## 9. Post-implementation defect found during spec reconciliation (pending)

> Found while reconciling `specs/nodes-page/spec.md` with the implemented code: `NodeListFilterBar` never invokes its `OnFilterChanged` EventCallback. The controls only `@bind-Value` into the shared `Filter` instance, so the parent `Nodes.razor` is not re-rendered when a filter changes — live filtering takes effect only after an unrelated parent re-render (refresh, navigation, reset). The spec requirement "Node list filter bar with four filters" keeps the live-filter semantics; this task closes the gap.

- [x] 9.1 Wire `OnFilterChanged` in `Components/Nodes/Shared/NodeListFilterBar.razor` so every control mutation notifies the parent (`@bind-Value:after` on the four controls, `Immediate="true"` on the name field for live filtering; parent's `StateHasChanged` re-computes `filteredNodes`).
