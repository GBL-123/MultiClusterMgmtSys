# 节点管理 - 功能设计文档

> 范围说明：本文档仅覆盖**后端功能**与**组件**设计，不包含前端页面布局/视觉设计。

---

## 1. 概述

### 1.1 功能目标

为多集群管理系统提供 Kubernetes 节点维度的观测能力：

1. **节点列表**：展示选定集群下全部节点的概要信息（名称、状态、角色、版本、地址等）。
2. **单节点下钻**：点击某一节点后，展示该节点的详细信息（容量、可分配资源、条件、污点、标签、注解、系统信息等）。
3. **独立入口与集群选择**：通过侧边栏「节点管理」导航独立进入，页面左侧提供集群选择栏目，选择集群后展示该集群下的全部节点；同时保留从集群管理下钻进入的入口。

### 1.2 功能范围

| 项 | 是否包含 |
| --- | --- |
| 节点列表（只读观测） | ✅ |
| 单节点详情下钻（只读观测） | ✅ |
| 节点编辑 / 封锁 / 排空 / 污点管理 | ❌（后续扩展） |
| 节点历史数据持久化 | ❌（节点数据实时拉取，不落库） |

### 1.3 设计原则

- **复用优先**：节点列表复用现有 `ClusterService.GetClusterNodesAsync` 与 `ClusterNodeViewModel`；详情在列表基础上扩展。
- **实时拉取**：节点状态动态变化，数据每次从 k8s 实时读取，不持久化到 `clusters.db`，与现有 `ClusterInfo.NodeCount` 的处理思路一致。
- **降级容错**：集群不可达或节点不存在时，捕获异常并给出明确状态，不影响应用与其他集群功能。
- **分层一致**：遵循现有 `Repository → Service → ViewModel → Razor 组件` 分层与编码规范（`[Inject]` 写在 `@code` 块内）。

## 2. 整体架构

### 2.1 与现有架构的关系

```
Components/Pages/
  Clusters.razor              集群列表（已有）
  ClusterDetail.razor         集群详情（已有，含基础节点列表）—— 增加下钻入口
  Nodes.razor                 节点列表页（新增，双入口：/nodes 与 /nodes/{id}）
  NodeDetail.razor            节点详情页（新增，下钻目标）
  MainLayout.razor            全局布局（已有 /nodes 导航项，无需改动）

Services/
  ClusterService.cs           扩展：新增 GetNodeDetailAsync / MapNodeDetail

ViewModels/
  ClusterNodeViewModel.cs         复用（列表项）
  ClusterNodeDetailViewModel.cs   新增（详情）
  NodeAddressViewModel.cs         新增
  NodeConditionViewModel.cs       新增
  NodeTaintViewModel.cs           新增
  NodeSystemInfoViewModel.cs      新增

Daos/
  ClusterRepository.cs        无需改动（节点不落库，仅用 GetByIdAsync 取集群连接信息）
```

### 2.2 数据流

```
用户 → Nodes.razor / NodeDetail.razor
     → ClusterService.GetClusterNodesAsync / GetNodeDetailAsync
     → ClusterRepository.GetByIdAsync（取 ClusterInfo 连接信息）
     → BuildConfig（依据 KubeConfig 或 Token 构建 KubernetesClientConfiguration）
     → Kubernetes(CoreV1).ListNodeAsync / ReadNodeAsync
     → MapNode / MapNodeDetail（V1Node → ViewModel）
     → 返回组件渲染
```

### 2.3 节点数据来源说明

- 节点信息来自 Kubernetes `CoreV1` API，**不写入数据库**。
- 数据库仅存储集群连接凭据（`ClusterInfo.KubeConfig` / `Token`），用于构建 k8s client。
- 因此节点管理功能**不涉及 `AppDbContext` 模型变更**，无需删除/重建 `clusters.db`。

### 3.3 Service 层设计（`ClusterService`）

#### 3.3.1 复用 `GetClusterNodesAsync`（列表，已存在）

```csharp
public async Task<List<ClusterNodeViewModel>> GetClusterNodesAsync(int id)
```

- 已实现：取 `ClusterInfo` → `BuildConfig` → `CoreV1.ListNodeAsync()` → `MapNode`。
- 节点列表页直接复用，无需改动。

#### 3.3.2 新增 `GetNodeDetailAsync`（详情）

```csharp
public async Task<ClusterNodeDetailViewModel?> GetNodeDetailAsync(int clusterId, string nodeName)
```

**职责**：读取指定集群下单个节点的详细信息。

**实现要点**：

1. `repo.GetByIdAsync(clusterId)` 取集群实体；不存在则返回 `null`。
2. `BuildConfig(entity)` 构建 k8s 配置（复用现有私有方法，支持 KubeConfig / Token 两种连接方式）。
3. `using var client = new Kubernetes(config);`
4. `var node = await client.CoreV1.ReadNodeAsync(nodeName);` 读取单节点。
   - 使用 `ReadNodeAsync(name)` 而非 `ListNodeAsync()` 后过滤，避免拉取全量节点列表，提升大集群下钻性能。
5. `MapNodeDetail(node, entity)` 映射为 `ClusterNodeDetailViewModel`，并回填 `ClusterId` / `ClusterName` / `IsReachable = true`。
6. 异常处理见 3.4。

#### 3.3.3 新增私有 `MapNodeDetail`

```csharp
private static ClusterNodeDetailViewModel MapNodeDetail(V1Node node, ClusterInfo cluster)
```

**映射规则**（与现有 `MapNode` 保持概要字段一致，便于列表与详情摘要对齐）：

| ViewModel 字段 | k8s 源字段 | 说明 |
| --- | --- | --- |
| Name | `node.Metadata.Name` | |
| Status | `node.Status.Conditions` 中 `Type=="Ready"` | `True→Ready`，否则 `NotReady`，无则 `Unknown` |
| Roles | `node.Metadata.Labels` 中 `node-role.kubernetes.io/*` 前缀 | 逗号拼接 |
| KubeletVersion | `node.Status.NodeInfo.KubeletVersion` | |
| OsImage | `node.Status.NodeInfo.OsImage` | |
| InternalIP | `node.Status.Addresses` 中 `Type=="InternalIP"` | |
| Uid | `node.Metadata.Uid` | |
| CreatedAt | `node.Metadata.CreationTimestamp` | |
| Unschedulable | `node.Spec.Unschedulable` | |
| PodCIDR | `node.Spec.PodCIDR` | |
| Phase | `node.Status.Phase` | |
| Addresses | `node.Status.Addresses` | 全量映射 |
| Conditions | `node.Status.Conditions` | 全量映射 |
| Taints | `node.Spec.Taints` | 全量映射，可能为 null |
| Capacity | `node.Status.Capacity` | 资源量→字符串（k8s 以 Quantity 字符串表示） |
| Allocatable | `node.Status.Allocatable` | |
| Labels | `node.Metadata.Labels` | |
| Annotations | `node.Metadata.Annotations` | |
| SystemInfo | `node.Status.NodeInfo` | 逐字段映射 |

> 说明：`MapNode`（列表用）与 `MapNodeDetail`（详情用）的概要字段计算逻辑相同，可将"计算 Ready 状态 / Roles / InternalIP"抽取为私有静态辅助方法，供二者复用，避免重复。

#### 3.3.4 k8s 客户端调用说明

- 复用现有 `BuildConfig(ClusterInfo cluster)`，已支持 `KubeConfig`（`BuildConfigFromConfigFile`）与 `Token`（`Host` + `AccessToken` + `SkipTlsVerify`）两种连接方式。
- `Kubernetes` 实例使用 `using` 确保释放。
- 调用 `CoreV1.ReadNodeAsync(string name)`，对应 `GET /api/v1/nodes/{name}`。

### 3.4 异常与降级处理

| 场景 | 处理 |
| --- | --- |
| 集群 `Id` 不存在 | `GetNodeDetailAsync` 返回 `null`，组件渲染"未找到"态 |
| 集群 `Status == Offline` | 直接返回 `IsReachable=false` 的空详情（不发起 k8s 调用），与 `GetClusterDetailAsync` 现有降级逻辑一致 |
| k8s 调用抛异常（网络/鉴权/超时） | `logger.LogError` 记录；向上抛出，由组件 `try/catch` 后以 `Snackbar` 提示"加载节点详情失败" |
| 节点名不存在（404） | k8s client 抛 `k8s.Autorest.HttpOperationException`，组件提示"节点不存在或已移除" |

> 与现有 `ProbeAsync` 的容错策略保持一致：集群不可达**不致命**，不影响应用与其他集群功能。

### 3.5 映射扩展（可选）

`ClusterNodeDetailViewModel` 由 `V1Node` 直接映射，**不经过 `ClusterInfo` 实体**，因此无需在 `ClusterMappingExtensions` 中新增扩展方法。`ClusterId` / `ClusterName` 由 Service 在映射后回填。

### 4.2 `Nodes.razor`（节点列表页）

**路由与参数**

```razor
@attribute [Authorize]
@page "/nodes"
@page "/nodes/{ClusterId:int}"
```

```csharp
[Parameter] public int? ClusterId { get; set; }
```

> **双入口设计**：`/nodes` 为侧边栏独立入口，`ClusterId` 为 null，页面左侧展示集群选择栏目、右侧展示空状态提示；`/nodes/{ClusterId:int}` 为集群下钻入口或侧边栏选择集群后的状态，`ClusterId` 有值，左侧集群选择栏高亮当前集群、右侧展示节点列表。选择集群后通过 `NavigationManager.NavigateTo($"/nodes/{id}")` 跳转，使两种入口在选中集群后统一为同一 URL 状态，便于链接分享。

**注入**

```csharp
[Inject] private ClusterService ClusterService { get; set; } = default!;
[Inject] private ISnackbar Snackbar { get; set; } = default!;
[Inject] private NavigationManager NavigationManager { get; set; } = default!;
```

> `ClusterService.GetClustersAsync()` 已存在，用于加载左侧集群选择栏的集群列表，无需新增 Service 方法。`ClusterViewModel` 已携带 `GroupId` / `GroupName`，前端按 `GroupName` 分组渲染为二级树（分组 → 集群），`GroupName == null` 归入「未分组」。

**状态字段**

```csharp
private List<ClusterViewModel> clusters = new();      // 全部集群（供左侧集群选择栏）
private List<ClusterNodeViewModel> nodes = new();
private ClusterDetailViewModel? cluster;              // 当前选中集群详情（右侧上下文摘要）
private bool loadingClusters;                         // 集群列表加载中
private bool loading;                                  // 节点列表加载中
private string searchName = "";                        // 节点名称过滤（前端过滤）
private string clusterSearch = "";                     // 集群名称过滤（左侧栏前端过滤）
private int? previousClusterId;                        // 用于 OnParametersSetAsync 检测参数变化

// 分组树节点（供左侧 MudTreeView 渲染）
private sealed class ClusterGroupNode
{
    public string Name { get; set; } = "";
    public List<ClusterViewModel> Clusters { get; set; } = new();
}

// groupedClusters：按 GroupName 分组，"未分组" 排最后，其余按名称字母序
```

**生命周期**

- `OnInitializedAsync` → `LoadClustersAsync`：
  - 加载全部集群列表 `clusters = await ClusterService.GetClustersAsync()`，供左侧集群选择栏渲染。
- `OnParametersSetAsync`：
  - 检测 `ClusterId` 是否变化（与 `previousClusterId` 比较）。
  - 若 `ClusterId` 有值且变化 → 调用 `LoadNodesAsync(ClusterId.Value)`：先取 `GetClusterDetailAsync`（集群摘要 + 可达性），若可达再取 `GetClusterNodesAsync`。
  - 若 `ClusterId` 为 null → 清空 `nodes` 与 `cluster`，右侧展示"请选择集群"空状态。
  - 更新 `previousClusterId`。

**交互**

- 左侧集群选择栏（`MudTreeView` 二级树）点击集群叶子节点 → `SelectCluster(int id)` → `NavigationManager.NavigateTo($"/nodes/{id}")`，由路由参数变化触发 `OnParametersSetAsync` 加载节点。一级分组目录仅用于展开/折叠，不触发导航。
- 节点名称可点击 → `NavigateToNode(string nodeName)` → `NavigationManager.NavigateTo($"/nodes/{ClusterId}/{nodeName}")`（下钻）。
- "返回集群详情"按钮 → `/clusters/{ClusterId}`（仅 ClusterId 有值时显示）。
- "刷新"按钮 → 重新 `LoadNodesAsync(ClusterId.Value)`。
- 节点名称搜索：前端 `filteredNodes` 计算（`searchName` 包含匹配），与 `Clusters.razor` 的前端过滤模式一致。

**降级态**

- `ClusterId is null` → 右侧内容区展示"请从左侧选择一个集群"空状态提示。
- `clusters.Count == 0` → 左侧集群选择栏展示"暂无集群"；`groupedClusters` 为空（搜索无匹配）时展示"没有匹配的集群"。
- `cluster is null`（ClusterId 有值但集群不存在）→ "未找到该集群"。
- `!cluster.IsReachable` → "集群不可达，无法获取节点列表"。
- `nodes.Count == 0` → "暂无节点数据"。
- `loading` → `MudProgressLinear`。

### 4.3 `NodeDetail.razor`（节点详情页）

**路由与参数**

```razor

```


> `NodeName` 为路由参数（string）。k8s 节点名允许小写字母、数字、`-`、`.`，路由约束默认即可；若需严格约束可加 `{NodeName:regex^[a-z0-9.-]+$}`，非必需。

**注入**

```csharp
[Inject] private ClusterService ClusterService { get; set; } = default!;
[Inject] private ISnackbar Snackbar { get; set; } = default!;
[Inject] private NavigationManager NavigationManager { get; set; } = default!;
```

**状态字段**

```csharp
private ClusterNodeDetailViewModel? node;
private bool loading;
```

**生命周期**

- `OnInitializedAsync` → `LoadAsync`：`node = await ClusterService.GetNodeDetailAsync(ClusterId, NodeName);`
- 因详情页可能从列表页通过浏览器前进/后退切换，`OnParametersSetAsync` 中若 `ClusterId` 或 `NodeName` 变化需重新加载。

**交互**

- "返回节点列表" → `/nodes/{ClusterId}`。
- "刷新" → 重新 `LoadAsync`。

**降级态**

- `node is null` → "未找到该节点"（集群不存在 / 节点不存在 / 集群离线）。
- `loading` → `MudProgressLinear`。
- 加载异常 → `Snackbar.Add($"加载节点详情失败: {ex.Message}", Severity.Error)`。

**展示数据分组**（仅说明数据归属，不规定布局）

详情页将 `ClusterNodeDetailViewModel` 的字段按以下逻辑分组供渲染：

- 概要：Name / Status / Roles / KubeletVersion / OsImage / InternalIP
- 调度：Unschedulable / Phase / PodCIDR
- 地址列表：Addresses
- 条件列表：Conditions
- 资源：Capacity / Allocatable
- 污点：Taints
- 标签：Labels
- 注解：Annotations
- 系统信息：SystemInfo
- 元数据：Uid / CreatedAt

### 4.4 与现有组件的集成（`ClusterDetail.razor` 改造）

现有 `ClusterDetail.razor` 已含"节点列表"卡片（`MudTable`，6 列）。改造点：

1. 节点列表卡片标题区增加"查看全部 / 节点管理"入口按钮 → 跳转 `/nodes/{Id}`。
2. 节点行 `Name` 单元格改为可点击 → 跳转 `/nodes/{Id}/{nodeName}`（下钻）。
3. 其余逻辑保持不变。

> 该改造为可选项。若希望 `ClusterDetail` 保持精简，也可仅在 `Clusters.razor` 集群列表行操作列增加"节点"入口按钮，跳转到 `Nodes.razor`。两种入口可并存。

### 4.5 路由设计

| 路由 | 组件 | 说明 |
| --- | --- | --- |
| `/nodes` | `Nodes.razor` | 节点管理独立入口（侧边栏），未选择集群，左侧集群选择栏 + 右侧空状态 |
| `/nodes/{ClusterId:int}` | `Nodes.razor` | 节点列表（已选择集群，侧边栏选择或集群下钻进入） |
| `/nodes/{ClusterId:int}/{NodeName}` | `NodeDetail.razor` | 节点详情（下钻） |

- `/nodes` 为侧边栏「节点管理」导航的目标路由，对应 `MainLayout.razor` 中已有的 `MudNavLink Href="/nodes"`。
- `/nodes/{ClusterId:int}` 兼顾两种进入方式：从 `/nodes` 选择集群后跳转而来，或从集群详情下钻而来。
- 节点详情路由独立于集群路由之下，保持 URL 语义层级清晰：`集群列表 → 集群详情` 与 `节点管理 → 节点列表 → 节点详情` 两条独立路径。

### 4.6 交互流程

```
入口一：侧边栏「节点管理」
  侧边栏 /nodes（空状态 + 左侧集群选择栏）
     └─ 选择集群 ──> /nodes/{id}（左侧栏高亮当前 + 右侧节点列表）
                        └─ 点节点名 ──> /nodes/{id}/{name}（节点详情，下钻）

入口二：集群管理下钻
  集群列表 /clusters
     └─ 点击集群名 ──> 集群详情 /clusters/{id}            （已有）
                           └─ "节点管理" / 点节点名 ──> /nodes/{id}   （新增）
                                                          └─ 点节点名 ──> /nodes/{id}/{name} （新增，下钻）
```

两条入口在选中集群后统一为 `/nodes/{id}`，节点列表页布局一致（左侧集群选择栏 + 右侧节点表格），区别仅在于进入路径。

下钻采用**独立详情页**而非弹窗，理由：节点详情字段量大（容量/条件/污点/标签/注解/系统信息），弹窗信息密度不足且不利于链接分享与浏览器历史导航。

## 6. 非功能设计

### 6.1 性能

- 节点详情使用 `CoreV1.ReadNodeAsync(name)`（单节点 GET），而非 `ListNodeAsync` 全量拉取后过滤，大集群下钻响应更快。
- 节点列表与集群详情的节点拉取存在重复调用 `ListNodeAsync` 的情况（`GetClusterDetailAsync` 内部已调一次）。若后续出现性能问题，可考虑在 `ClusterService` 内做请求级缓存（scoped 实例内短时缓存 `ListNodeAsync` 结果），当前规模下非必需。

### 6.2 安全

- 所有节点页面均加 `@attribute [Authorize]`，与 `Clusters.razor` / `ClusterDetail.razor` 一致，未登录不可访问。
- 节点详情中的 `Labels` / `Annotations` 可能包含业务敏感信息，渲染时不做特殊脱敏（与现有"连接信息密文显隐"机制不同）；若后续有合规要求，可对注解中常见密钥前缀（如 `kubernetes.io/`、`node.alpha.kubernetes.io/`）做折叠处理。
- 节点管理为只读观测，不涉及写操作，无需 `AuthorizeView Roles="Admin"` 限制；普通登录用户即可查看。写操作（封锁/排空等）留待后续扩展时再按角色控制。

### 6.3 错误处理

- 统一在组件 `LoadAsync` 内 `try/catch`，`Snackbar` 提示，与现有页面错误处理模式一致。
- Service 层异常向上抛，不在 Service 内吞掉（除 `ProbeAsync` 这种"探测并改写状态"的场景）。

### 6.4 一致性

- 节点 `Status`（Ready/NotReady/Unknown）的计算逻辑在 `MapNode` 与 `MapNodeDetail` 中必须一致，建议抽取共用辅助方法。
- 节点列表页与集群详情页的节点列表展示同一份数据源（`GetClusterNodesAsync`），字段含义一致。

## 7. 后续扩展（可选，不在本期范围）

- **节点写操作**：封锁 / 解封（`cordon`/`uncordon`）、排空（`drain`）、污点增删，需引入 `AuthorizeView Roles="Admin"` 与对应 `CoreV1` 写 API。
- **Pod 维度下钻**：节点详情页增加该节点上运行的 Pod 列表（`CoreV1.ListPodForAllNamespacesAsync(fieldSelector: spec.nodeName=...)`）。
- **资源使用率**：接 metrics-server（`metrics.k8s.io`）展示节点 CPU/内存实时使用量与可分配占比。
- **节点缓存**：若节点列表频繁刷新，可在 scoped `ClusterService` 内对 `ListNodeAsync` 结果做短时缓存，降低 k8s API 压力。
- **节点历史**：持久化节点快照与状态变更历史，支持离线集群回看（需新增 `NodeSnapshot` 实体与迁移，与当前"实时拉取不落库"策略不同，需单独评估）。
