# 集群管理页面功能设计文档

> 状态：设计阶段（未编码） · 适用页面：`Components/Pages/Clusters.razor` 及相关组件/服务

## 1. 设计目标

围绕集群管理页面的三大核心能力进行重新设计：**添加集群**、**展示已添加集群**、**按字段过滤**，并扩展编辑、详情、排序等能力，使其从「能用」升级为「好用」的日常运维管理界面。

### 1.1 范围（本期纳入）

| 能力 | 说明 |
|---|---|
| 添加集群 | 支持 **kubeconfig** 与 **token** 两种连接方式；kubeconfig 支持粘贴文本与文件上传 |
| 集群展示 | **表格视图**（`MudTable`，表头排序） |
| 过滤筛选 | 名称关键词 + 状态 + 分组 + 版本 + 创建时间范围，多条件 AND 组合 |
| 列表排序 | 按名称/状态/节点数/创建时间排序 |
| 编辑集群 | 重命名、改分组、更新连接配置（可在两种连接方式间切换） |
| 集群详情页 | 独立路由页，展示完整信息 + 节点列表 + 连接配置 |

### 1.2 范围外（本期不做）

- 批量操作（批量刷新/删除/移动分组）
- 一键刷新全部 / 自动定时刷新
- 集群导出
- 多用户/权限

> 上述能力已与需求方确认排除，可在后续迭代再加。

## 2. 现状与差距

### 2.1 现有实现（`Clusters.razor`）

- 左侧分组侧边栏（"全部集群" + 各分组，带数量徽标，hover 显示删除）
- 右侧集群卡片网格（名称、状态 chip、版本、节点数、分组、API Server、创建时间）
- 卡片操作：刷新状态、删除
- 添加集群 Dialog：名称 + 分组 + API Server + kubeconfig 纯文本粘贴
- 过滤仅靠侧边栏分组切换

### 2.2 主要差距

| 差距 | 影响 |
|---|---|
| 过滤维度单一（仅分组） | 无法按名称/状态/版本快速定位集群 |
| 无编辑 | 改名/换分组/更新配置只能删除重建，丢失历史 |
| 无详情页 | 节点列表等深信息无处展示 |
| 仅 kubeconfig 粘贴 | 无文件上传；不支持 token 直连（内网/临时环境常见） |
| 无排序 | 列表顺序固定为 DB 顺序 |
| 仅卡片视图 | 集群多时信息密度低，管理效率差 |
| 状态仅 Online/Offline/Unknown | 无"上次检查时间"，无法判断数据新鲜度 |

## 3. 数据模型变更

> ⚠️ 本仓库**无 EF 迁移**，schema 由 `EnsureCreated()` 生成。改模型后必须删除 `clusters.db*` 重建库（见 AGENTS.md）。所有模型变更集中一次完成。

### 3.1 `ClusterInfo` 新增字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ConnectionType` | `ConnectionType` (enum) | 连接方式：`KubeConfig=0` / `Token=1`。决定用 `KubeConfig` 还是 `Token` 字段连集群 |
| `Token` | `string?` | Token 模式的 Bearer Token（明文存储，见 §8 安全说明） |
| `SkipTlsVerify` | `bool` | 是否跳过 TLS 校验（token 模式常见自签证书，默认 `true`） |
| `LastCheckedAt` | `DateTime?` | 上次状态检查时间，详情页/列表展示数据新鲜度 |

`KubeConfig`、`ApiServer` 字段保留不变。

### 3.2 新增枚举 `ConnectionType`

```csharp
public enum ConnectionType { KubeConfig, Token }
```

### 3.3 新增节点 DTO（不持久化，运行时拉取）

```csharp
public class ClusterNodeInfo
{
    public string Name { get; set; } = "";
    public string Status { get; set; } = "";      // Ready / NotReady
    public string Roles { get; set; } = "";        // control-plane / worker
    public string KubeletVersion { get; set; } = "";
    public string OsImage { get; set; } = "";
    public string InternalIP { get; set; } = "";
}
```

### 3.4 `AppDbContext` 调整

- `ClusterInfo` 配置中补 `Token`（`HasColumnType("TEXT")`，同 `KubeConfig`）、`SkipTlsVerify`（默认 `true`）、`LastCheckedAt`。
- 无需调整关系映射。

## 4. 功能详细设计

### 4.1 添加集群（`AddClusterDialog` 重设计）

**连接方式切换**：Dialog 顶部用 `MudToggleGroup` 二选一。

#### 方式 A：KubeConfig

| 字段 | 控件 | 校验 |
|---|---|---|
| 集群名称 | `MudTextField` | 必填 |
| 所属分组 | `MudSelect`（含"无分组"） | 可选 |
| API Server | `MudTextField` | 可选，留空从 kubeconfig 解析 |
| KubeConfig 输入 | **二级切换**：粘贴文本（`MudTextField Lines=10`）/ 上传文件（`InputFile`，接受 `.yaml/.yml/.config`，限制大小如 256KB） | 二选一必填 |

文件上传读取为文本后与粘贴等价处理，填入 `KubeConfig`。

#### 方式 B：Token

| 字段 | 控件 | 校验 |
|---|---|---|
| 集群名称 | `MudTextField` | 必填 |
| 所属分组 | `MudSelect` | 可选 |
| API Server | `MudTextField` | **必填**（如 `https://10.0.0.1:6443`） |
| Bearer Token | `MudTextField Lines=4`（可配密码态显示/隐藏） | 必填 |
| 跳过 TLS 校验 | `MudCheckBox` | 默认勾选 |

#### 提交行为

- 提交即建集群记录（状态 `Unknown`），随后立即尝试连接探测（复用现有 `AddClusterAsync` 的探测逻辑，扩展为按 `ConnectionType` 分支构建 client）。
- 连接成功 → 状态 `Online`，回填 `Version`/`NodeCount`/`ApiServer`/`LastCheckedAt`。
- 连接失败 → 状态 `Offline`，记录日志，**不阻断添加**（集群记录仍保留，用户可稍后修正）。

### 4.2 集群展示（表格视图）

列表区只保留**表格视图**（`MudTable`），不再有卡片视图与视图切换控件。

`MudTable` 列：

| 列 | 说明 | 可排序 |
|---|---|---|
| 名称 | 可点击进入详情 | 是 |
| 状态 | chip 展示 | 是 |
| 版本 | k8s 版本 | 是 |
| 节点数 | 数字 | 是 |
| 分组 | 名称 / "未分组" | 否 |
| API Server | 截断显示 | 否 |
| 创建时间 | `yyyy-MM-dd HH:mm` | 是 |
| 操作 | 刷新 / 编辑 / 删除 | 否 |

- 表头点击排序（`MudTable` 内置 `MudTableSortLabel`），支持升降序切换
- 名称列点击进入详情页

### 4.3 过滤筛选

**布局策略**：取消左侧分组侧边栏，所有过滤维度合并进内容区顶部**工具栏**，多条件 AND 组合：

```
最终结果 = 分组 AND 名称 AND 状态 AND 版本 AND 创建时间范围
```

工具栏控件（一行排列，响应式换行）：

| 维度 | 控件 | 行为 |
|---|---|---|
| 名称搜索 | `MudTextField` 带搜索图标 | 实时（防抖 ~300ms）模糊匹配 `Name` |
| 分组 | `MudSelect` | 「全部分组」+ 各分组；单选 |
| 状态 | `MudSelect`（全部/在线/离线/未知） | 单选 |
| 版本 | `MudSelect` | 选项来自当前所有集群的 distinct `Version`（含"未知"代表 null） |
| 开始时间 | `MudDatePicker` | 按集群 `CreatedAt` 过滤；选某日含当日 00:00 起；留空表示不限下界 |
| 结束时间 | `MudDatePicker` | 按集群 `CreatedAt` 过滤；选某日含当日全天（即 `< 次日 00:00`）；留空表示不限上界 |

- 工具栏右侧放"重置"按钮清空所有筛选条件（含两个时间选择器）
- 空结果时显示空状态文案 + "重置筛选"快捷入口
- 分组的新建/删除改由工具栏「分组管理」按钮打开对话框承载（见布局设计文档 §5）

### 4.4 列表排序

- **表格视图**：点击表头排序（§4.2 已含），支持升降序切换。
- 排序入口唯一，不再有卡片视图的排序下拉。

### 4.5 编辑集群信息（新增 `EditClusterDialog`）

结构与 `AddClusterDialog` 镜像，预填当前值：

- 集群名称（可改）
- 所属分组（可改）
- 连接配置：顶部切换 KubeConfig / Token（**允许切换连接方式**），按所选方式展示对应字段，预填当前 `KubeConfig`/`Token`/`ApiServer`/`SkipTlsVerify`
- 保存时若连接配置变更 → 保存后立即重新探测状态；若仅改名/换分组 → 不触发探测

服务层新增 `UpdateClusterAsync(int id, ...)`。

### 4.6 集群详情页（新增，路由 `/clusters/{Id:int}`）

独立页面 `ClusterDetail.razor`，从列表表格的名称列点击进入。

#### 信息分区

1. **基本信息**：名称、状态（chip + 上次检查时间）、创建时间
2. **连接信息**：连接方式、API Server、kubeconfig/token（默认掩码，点击"显示"查看明文）
3. **集群概览**：k8s 版本、节点数
4. **节点列表**：**实时从 k8s 拉取**（调用 `GetClusterNodesAsync`），表格展示：名称 / 状态 / 角色 / kubelet 版本 / OS / 内网 IP
   - 离线/不可达集群：显示"集群不可达，无法获取节点列表"占位
   - 拉取中显示 loading
5. **操作区**：刷新状态、编辑、删除、返回列表

#### 设计要点

- 节点列表不持久化，每次进详情页实时拉取（保证新鲜，且离线集群不阻塞页面）
- 进入页面时若状态为 `Offline`，节点列表区直接降级，不发起注定失败的请求

## 5. 交互流程

### 5.1 添加集群

```
点"添加集群" → 选连接方式 → 填表单 → 提交
  → 建记录(状态 Unknown) → 立即探测
    → 成功：Online，回填版本/节点数/上次检查
    → 失败：Offline，记录日志，仍保留记录
  → 关闭 Dialog → 刷新列表
```

### 5.2 过滤 + 排序

```
工具栏选分组(可选) + 输入名称/选状态/选版本/选时间范围
  → filteredClusters 实时重算(防抖)
  → 表格视图同步更新
  → 点表头 → 排序生效
```

### 5.3 编辑集群

```
点"编辑" → EditClusterDialog(预填) → 改字段 → 保存
  → 仅改名/分组：直接保存
  → 改连接配置：保存后重新探测 → 更新状态
  → 关闭 Dialog → 刷新列表
```

### 5.4 查看详情

```
点表格名称列 → 跳转 /clusters/{id}
  → 加载集群信息
  → 若非 Offline：实时拉取节点列表
  → 展示分区信息
```

## 6. 服务层改动（`ClusterService`）

| 方法 | 改动 |
|---|---|
| `AddClusterAsync` | 新增 `connectionType`、`token`、`skipTlsVerify` 参数；探测逻辑按连接方式分支构建 client |
| `UpdateClusterAsync`（新增） | 更新名称/分组/连接配置；连接配置变更时重新探测 |
| `RefreshClusterStatusAsync` | 按 `ConnectionType` 分支构建 client；更新 `LastCheckedAt` |
| `GetClusterNodesAsync`（新增） | 按 `ConnectionType` 构建 client，`CoreV1.ListNodeAsync()` 解析为 `List<ClusterNodeInfo>`；离线抛异常由调用方降级 |
| 私有 `BuildK8sClient(ClusterInfo)`（新增） | 抽取连接逻辑：KubeConfig 走 `BuildConfigFromConfigFile(stream)`；Token 走手动 `KubernetesClientConfiguration { Host, AccessToken, SkipTlsVerify }` |

### 连接逻辑分支

- **KubeConfig 模式**：`KubernetesClientConfiguration.BuildConfigFromConfigFile(stream)`（现有逻辑）
- **Token 模式**：构造 `KubernetesClientConfiguration`，设 `Host = ApiServer`、`AccessToken = Token`、`SkipTlsVerify = skipTlsVerify`，再 `new Kubernetes(config)`

## 8. 风险与注意事项

1. **模型变更须重建库**：新增 `ConnectionType`/`Token`/`SkipTlsVerify`/`LastCheckedAt` 触发 schema 变更，必须删除 `clusters.db*` 重跑（无迁移，见 AGENTS.md）。建议所有模型改动一次性完成。
2. **敏感信息明文存储**：`KubeConfig`/`Token` 以明文 TEXT 存于 SQLite，与现状一致。本系统定位为开发/内部工具，不做加密；详情页展示时默认掩码，需主动点击显示。若未来用于生产环境需增加加密层。
3. **InputFile 与 Blazor Server**：`InputFile` 在 Server 模式下读取为流，kubeconfig 文件小（<256KB）无性能问题；需设上限防滥用。
4. **离线集群降级**：详情页节点列表依赖实时 k8s 连接，离线集群直接降级展示，不发起无效请求，避免长超时等待。
5. **token 模式 TLS**：自签证书在开发环境常见，`SkipTlsVerify` 默认 `true`；UI 需提示安全风险。
6. **版本筛选选项来源**：来自当前已加载集群的 distinct `Version`，含 null（显示"未知"）；集群刷新后版本变化需重新加载列表以更新选项。
