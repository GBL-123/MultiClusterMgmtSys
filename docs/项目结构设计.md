# 项目结构设计文档

> 状态：设计阶段（待评审） · 适用：整个 `MultiClusterMgmtSys` 项目
> 本文档定义分层架构、各目录职责、ViewModel 契约与数据流，不给出实现代码。

---

## 1. 设计目标与分层原则

围绕两条核心约束重新组织后端：

- **Daos/**：存放所有「与数据库交互」的操作类。纯持久化层，只返回/接收实体，不感知前端、不做 k8s 调用。
- **Services/**：存放所有「与前端直接交互」的类。门面/编排层，组合 Repository（DB）与 k8s 调用，**所有对外方法返回 ViewModel 而非实体**。

由此形成单向依赖与清晰的数据流：

```
前端(Razor) ──只依赖──▶ Services(返回ViewModel) ──依赖──▶ Daos/Repository(返回实体) ──依赖──▶ AppDbContext
                              │
                              └──依赖──▶ k8s(KubernetesClient)   [非DB，归Service层]
```

**硬约束（贯穿全项目）：**
- Service 不得返回实体类；Razor 不得直接引用 `Models/` 实体。
- Daos 不得返回 ViewModel、不得调用 k8s、不得注入 `IJSRuntime`/`IDialogService` 等 UI 服务。
- ViewModel 不得持有 EF 导航属性或 DbContext 引用；它是纯数据契约。

## 3. 各层职责与规则

### 3.1 Models/ — 持久化实体与枚举

- 只放 EF 实体（`ClusterGroup`、`ClusterInfo`）与值枚举（`ClusterStatus`、`ConnectionType`）。
- 实体可含导航属性（`ClusterInfo.Group`、`ClusterGroup.Clusters`），供 Repository Include 使用。
- 实体字段按功能设计文档扩展：`ClusterInfo` 新增 `ConnectionType`、`Token`、`SkipTlsVerify`、`LastCheckedAt`。
- **不得**在此放 ViewModel、不得放 DB 查询方法。

### 3.2 Daos/ — DbContext + Repository

- `AppDbContext`：保留，仅负责 EF 配置（DbSet、连接串、`OnModelCreating`）。不写业务查询。
- `ClusterRepository` / `GroupRepository`：封装所有 EF 查询与持久化，**返回实体**。
- 依赖注入 `AppDbContext`；生命周期随 DbContext（Scoped）。
- 可包含 `Include`、过滤、排序逻辑，但**不**做 k8s 调用、**不**装配 ViewModel。

### 3.3 ViewModels/ — 数据契约

- 所有 Service 与前端之间的数据契约，命名 `XxxViewModel`。
- 分两类：**输出 VM**（Service→前端，只读契约）与**输入 VM**（前端→Service，表单提交载荷）。
- 纯 POCO，无 EF 依赖、无导航属性、无行为方法。
- 映射放 `ViewModels/Mappings/`，以扩展方法实现 `entity.ToViewModel()`，集中可查。

### 3.4 Services/ — 前端门面

- 注入 Repository（DB）与 `ILogger`；`ClusterService` 内含 k8s 连接私有方法。
- 所有 public 方法**返回 ViewModel**（或 void/task for delete）。
- 职责：编排「读实体 → 调 k8s 探测/拉节点 → 装配 ViewModel」。
- **不得**返回实体；**不得**注入 `IDialogService`/`ISnackbar`（那是 Razor 的事，Service 只抛异常由调用方处理，现状已是如此，保留）。

### 3.5 Components/ — Blazor UI

- Pages/Dialogs 仅注入 Service，消费 ViewModel。
- 不得引用 `Models/` 实体、不得直接用 `AppDbContext`。
- UI 状态（loading/processing/筛选）留在 `.razor` 的 `@code`，不进 Service。

## 4. Repository 层设计

> 返回实体；Repository 不感知 ViewModel。

### 4.1 `ClusterRepository`

| 方法 | 返回 | 说明 |
|---|---|---|
| `GetAllAsync()` | `List<ClusterInfo>` | Include(Group)，全量 |
| `GetByIdAsync(int id)` | `ClusterInfo?` | Include(Group) |
| `AddAsync(ClusterInfo entity)` | `ClusterInfo` | 写入并返回（含生成 Id） |
| `UpdateAsync(ClusterInfo entity)` | `void` | 保存变更 |
| `DeleteAsync(int id)` | `void` | 删除 |

### 4.2 `GroupRepository`

| 方法 | 返回 | 说明 |
|---|---|---|
| `GetAllAsync()` | `List<ClusterGroup>` | Include(Clusters)，按 Id 排序 |
| `GetByIdAsync(int id)` | `ClusterGroup?` | |
| `AddAsync(ClusterGroup entity)` | `ClusterGroup` | |
| `DeleteAsync(int id)` | `void` | |

> Repository 方法粒度保持小而纯；事务编排（如「先保存集群再探测」）由 Service 协调，不在 Repository 内。

### 5.2 输入 ViewModel（前端→Service）

**`ClusterCreateViewModel`**（添加集群提交）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Name` | `string` | 必填 |
| `GroupId` | `int?` | |
| `ConnectionType` | `ConnectionType` | 决定用哪个密文 |
| `ApiServer` | `string?` | Token 模式必填 |
| `KubeConfig` | `string?` | KubeConfig 模式必填 |
| `Token` | `string?` | Token 模式必填 |
| `SkipTlsVerify` | `bool` | 默认 true |

**`ClusterUpdateViewModel`**（编辑集群提交，含 Id）

字段同 `ClusterCreateViewModel` + `Id`。

### 5.3 敏感数据策略

`KubeConfig`、`Token` 是明文存储的集群凭据：

- **列表 ViewModel**：一律不含密文。
- **详情 ViewModel**：不含密文；详情页的「显示密文」交互通过编辑预填（`ClusterEditViewModel`）或一个**显式密文查询方法**提供，避免普通详情请求把凭据带进内存/日志。
- 前端任何展示密文处默认掩码，点击「显示」才呈现明文。
- Service 日志不得打印密文（现状已用结构化日志占位，保持）。

## 6. Service 层设计

> 所有 public 方法返回 ViewModel（delete 类返回 task）。

### 6.1 `ClusterService`

| 方法 | 返回 | 编排 |
|---|---|---|
| `GetClustersAsync()` | `List<ClusterViewModel>` | repo.GetAll → 映射 |
| `GetClusterDetailAsync(int id)` | `ClusterDetailViewModel?` | repo.GetById → 若可连拉节点 → 装配 |
| `GetClusterForEditAsync(int id)` | `ClusterEditViewModel?` | repo.GetById → 含密文回填 |
| `AddClusterAsync(ClusterCreateViewModel)` | `ClusterViewModel` | 建实体 → repo.Add → k8s 探测 → repo.Update → 映射 |
| `UpdateClusterAsync(ClusterUpdateViewModel)` | `ClusterViewModel` | repo.GetById → 改字段 → 连接配置变更则重新探测 → repo.Update → 映射 |
| `DeleteClusterAsync(int id)` | `Task` | repo.Delete |
| `RefreshClusterStatusAsync(int id)` | `ClusterViewModel` | repo.GetById → k8s 探测 → repo.Update → 映射 |
| `GetClusterNodesAsync(int id)` | `List<ClusterNodeViewModel>` | repo.GetById → BuildK8sClient → ListNode → 映射（离线抛异常由调用方降级） |

私有方法：`BuildK8sClient(ClusterInfo)` — 按 `ConnectionType` 分支构建 `Kubernetes`（KubeConfig 走 `BuildConfigFromConfigFile`；Token 走手动 `KubernetesClientConfiguration`）。k8s 逻辑暂留 Service 内，不单独成层。

### 6.2 `GroupService`（新增，从 ClusterService 拆出分组职责）

| 方法 | 返回 |
|---|---|
| `GetGroupsAsync()` | `List<ClusterGroupViewModel>` |
| `AddGroupAsync(GroupCreateViewModel)` | `ClusterGroupViewModel` |
| `DeleteGroupAsync(int id)` | `Task` |

## 7. 数据流示意

### 7.1 列表加载

```
Clusters.razor ──GetClustersAsync()──▶ ClusterService
                                          └─▶ ClusterRepository.GetAllAsync() → List<ClusterInfo>
                                          └─▶ 映射 ToViewModel() → List<ClusterViewModel>
                       ◀──返回 ViewModel──
Razor 直接绑定渲染（卡片/表格）
```

### 7.2 添加集群

```
AddClusterDialog ──提交 ClusterCreateViewModel──▶ ClusterService.AddClusterAsync
                                                       └─▶ 构造 ClusterInfo 实体
                                                       └─▶ ClusterRepository.AddAsync (状态 Unknown)
                                                       └─▶ BuildK8sClient → 探测 → 改实体状态
                                                       └─▶ ClusterRepository.UpdateAsync
                                                       └─▶ 映射 → ClusterViewModel
                    ◀──返回 ViewModel──
Dialog 关闭 → 列表刷新
```

### 7.3 详情页

```
ClusterDetail.razor ──GetClusterDetailAsync(id)──▶ ClusterService
                                                     └─▶ repo.GetById → 实体
                                                     └─▶ 若 IsReachable：GetClusterNodesAsync（k8s）
                                                     └─▶ 装配 ClusterDetailViewModel（不含密文）
                    ◀──返回 ViewModel──
「显示密文」按钮 → GetClusterForEditAsync(id) 或显式密文方法 → 前端掩码呈现
```

## 8. 命名与依赖规则（硬约束）

1. ViewModel 统一 `XxxViewModel`，放 `ViewModels/`；实体放 `Models/`，二者物理隔离。
2. Repository 命名 `XxxRepository`，放 `Daos/`；返回实体，方法名用 `GetAll/GetById/Add/Update/Delete`。
3. Service 命名 `XxxService`，放 `Services/`；public 方法返回 ViewModel。
4. 映射用扩展方法 `entity.ToViewModel()`，放 `ViewModels/Mappings/`；禁止在实体类内写 `ToViewModel`。
5. `Program.cs` 注册：`AddDbContext`、`AddScoped<XxxRepository>`、`AddScoped<XxxService>`。
6. 禁止：Service 返回 `ClusterInfo`/`ClusterGroup`；Razor `@using MultiClusterMgmtSys.Models`（应改为 `ViewModels`）；Repository 注入 UI 服务。

## 9. 现有代码迁移影响

| 现状 | 迁移动作 |
|---|---|
| `Services/ClusterService.cs` 既查 DB 又调 k8s 又返回实体 | 拆分：DB 查询移入 `Daos/ClusterRepository`、`Daos/GroupRepository`；Service 改为编排 + 返回 ViewModel；分组方法移入新 `GroupService` |
| Service 直接返回 `ClusterInfo`/`ClusterGroup` | 新建 `ViewModels/` 全套 VM + 映射；Service 方法签名改为返回 VM；入参由散装基本类型改为 `ClusterCreateViewModel` 等 |
| `Clusters.razor` 注入 `ClusterService` 用实体 | 改为消费 `ClusterViewModel`；`@using` 调整；卡片字段绑定 VM |
| `AddClusterDialog` 散装字段提交 | 改为构造 `ClusterCreateViewModel` 提交 |
| `Program.cs` 只注册 `ClusterService` | 增加 `ClusterRepository`、`GroupRepository`、`GroupService` 注册 |

> ⚠️ 本仓库无 EF 迁移，模型字段扩展（`ConnectionType`/`Token`/`SkipTlsVerify`/`LastCheckedAt`）需删 `clusters.db*` 重建库（见 AGENTS.md）。建议模型字段与本次结构重构一并完成，一次性删库重跑。

## 10. 实现顺序建议

1. **模型扩展**：`Models/` 加 `ConnectionType` 枚举 + `ClusterInfo` 新字段；`AppDbContext` 配置补字段。
2. **Daos 层**：新建 `ClusterRepository`、`GroupRepository`，迁移现有查询逻辑。
3. **ViewModels 层**：建全部 VM + `Mappings/` 扩展方法。
4. **Services 层**：重写 `ClusterService`（返回 VM）+ 新建 `GroupService`；接入 k8s `BuildK8sClient` 分支。
5. **Program.cs**：注册新增 Repository/Service。
6. **Components 层**：`Clusters.razor` + Dialogs 改为消费 VM。
7. 删库重跑验证（`dotnet build` + 运行操作）。
